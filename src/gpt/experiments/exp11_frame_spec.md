# 실험 11 — 질문 해석 틀(Frame) 설계

> 목적: 키워드 규칙(`search.parse`) 대신 **MiniGPT가 질문을 이해해 '해석 틀'을 출력**하고, 답변은 이 틀만 보고 조립한다.
> 선생님 LLM(윈도우, Ollama)은 이 틀 형식으로 학습 데이터를 만들고, MiniGPT는 그걸 배운다. 서비스에서는 MiniGPT만 쓴다.
> 작성 2026-11-26 (MiniGPT 세션). 근거: 11주차 시연 로그 71건 분석 (ai.md 7장).

---

## 1. 원칙

1. **이름 찾기는 사전, 이해는 모델.** 챔피언·아이템·스킬 이름과 패치 번호는 정답이 정해진 사전 찾기로 찾아 자리표시(`[챔피언1]`, `[아이템1]`, `[패치1]`)로 바꾼다 (실험 10b에서 효과 확인). 누가 '나'이고 누가 '상대'인지, 무슨 의도인지, 몇 개를 답할지는 모델이 정한다.
2. **틀은 '무엇을 답할지'까지 담는다.** 의도는 여러 개 가능, 근거 개수(하나/전체), 상향·하향 방향, 사이트 밖 질문 여부까지.
3. **이어지는 질문은 이전 틀을 입력으로 준다.** 모델은 이전 틀 + 새 질문을 보고 **완성된 틀**을 출력한다 (이어받기를 모델이 판단).
4. **모르면 모른다.** 롤과 무관하거나 데이터 밖 질문은 `범위`로 걸러 안내 문구로 답한다. 아무 근거나 내지 않는다.

---

## 2. 입력

```
이전: 의도=템트리 나=[챔피언1] 라인=탑 | 질문: 상대는 [챔피언2]이야
```
- 첫 질문이면 `이전: 없음 | 질문: …`
- 자리표시 번호는 이전 틀과 질문을 통틀어 등장 순서대로 매긴다 (이전 틀의 챔피언이 `[챔피언1]`이면 새 질문의 챔피언은 `[챔피언2]`부터).
- 원래 이름 ↔ 자리표시 대응표는 서비스 코드가 들고 있다가 틀을 실제 이름으로 되돌린다.

---

## 3. 해석 틀 필드 (선생님 LLM 출력·정답 라벨 = 이 JSON)

| 필드 | 값 | 설명 |
|---|---|---|
| `범위` | `롤` / `사이트밖` / `데이터밖` | 사이트밖 = 잡담·인사·욕·롤과 무관한 정보 요청("오늘 날씨", "성현욱이 누구야"). 데이터밖 = 롤 질문이지만 우리 데이터로 답할 수 없음(스킬 상호작용 "아리 E플", 룬, 앞으로의 패치 예측 "레넥 상향 언제"). |
| `의도` | 아래 11개 중 **1~3개, 중요한 순** | `범위`가 롤일 때만 |
| `챔피언` | `[{"자리": "[챔피언1]", "역할": "나"/"상대"/"대상"/"맞대결"/"관계없음"}]` | 대상 = 나·상대 구도가 아닌 그냥 물어본 챔피언. 맞대결 (11/28 추가) = 두 챔피언이 맞붙는데 누가 나·상대인지 문장에 안 드러남("X vs Y", "X Y 맞라인 템트리") — 두 챔피언 모두 맞대결, 답은 양쪽 방향(X가 Y를 만날 때 / Y가 X를 만날 때)의 템트리·상대법을 다 보여 준다. 의도가 안 적혀 있으면("X vs Y") 상대법+템트리. 나·상대 표시("나 X", "상대 Y", "Y 상대로 X", "Y 나왔는데", 끝에서 템을 묻는 X)가 하나라도 있으면 맞대결이 아니라 나/상대. 관계없음 = 이름은 나왔지만 답과 무관("너가 렉사이야?") — **학습용 라벨일 뿐 틀에는 적지 않는다**(틀의 `챔피언`엔 나/상대/대상/맞대결만) |
| `아이템` | `"[아이템1]"` / null | |
| `스킬` | `패시브`/`Q`/`W`/`E`/`R`/`전체`/null | "궁" → R, "스킬 다" → 전체 |
| `라인` | `탑`/`정글`/`미드`/`원딜`/`서폿`/null | 질문에 라인이 있거나 이전 틀에서 이어받을 때만 |
| `역할군` | `탱커`/`전사`/`마법사`/`암살자`/`원딜`/`서포터`/null | 챔피언 추천 조건 |
| `난이도` | `쉬움`/null | "롤 처음인데", "초보" |
| `시점` | `최신`/`[패치1]`/`이력`/null | 이력 = "과거부터 지금까지" |
| `방향` | `상향`/`하향`/`변경`/null | "버프·좋아짐" → 상향, "너프" → 하향, "바뀐 거" → 변경 |
| `개수` | `하나`/`전체`/null | null이면 답 모듈 기본값. "하나만 추천" → 하나, "다 알려줘" → 전체 |
| `이어받음` | true/false | 이전 틀에서 값을 가져왔는지 (평가·화면 표시용, 예: "(다리우스 기준)") |

### 의도 11개

| 의도 | 뜻 | 쓰는 데이터 |
|---|---|---|
| `개요` | 챔피언이 어떤 챔피언인지 | profile, lore, skill |
| `스킬` | 스킬 설명 | skill |
| `패치` | 변경 내역 | patch_change |
| `이유` | 왜 바뀌었나 | patch_context |
| `능력치` | 기본 체력·공격력 등 | stats |
| `템트리` | 아이템 구매 순서 (상대 있으면 상성 반영) | build_stats + recommend |
| `상대법` | 상대를 어떻게 이기나·운영 팁 | 상대의 enemytips, 내 allytips, 맞대결 승률 |
| `성능` | "요즘 좋나", "OP야?" | build_stats 승률·경기 수 + 최근 패치 방향 |
| `아이템` | 아이템 효과·조합 | item |
| `추천` | 챔피언 추천 (조건: 역할군·라인·난이도) | profile 역할군 + Data Dragon 난이도 + 승률 |
| `안내` | "이거 뭐하는 사이트임" | 사이트 소개 + 예시 질문 |

## 4. 예시 (11주차 실제 질문)

| 입력 | 해석 틀 (요약) |
|---|---|
| `이전: 없음 \| 질문: 롤 처음인데 무슨 챔피언 할까` | 범위=롤, 의도=[추천], 난이도=쉬움, 개수=null |
| `이전: 없음 \| 질문: [챔피언1] 최근에 좋나?` (블츠) | 의도=[성능, 패치], 챔피언=[1:대상], 시점=최신, 방향=null |
| `이전: 없음 \| 질문: [챔피언1] Q 상향됐나?` (나서스) | 의도=[패치], 챔피언=[1:대상], 스킬=Q, 시점=최신, 방향=상향 |
| `이전: 없음 \| 질문: 내가 [챔피언1]이고 적이 [챔피언2]야 템트리 추천해줘` | 의도=[템트리], 챔피언=[1:나, 2:상대] |
| `이전: 없음 \| 질문: 미드 [챔피언1]인데 [챔피언2] 상대로 어떻게 이겨?` | 의도=[상대법, 템트리], 챔피언=[1:나, 2:상대], 라인=미드 |
| `이전: 없음 \| 질문: [챔피언1]의 스킬이 머야` (아우솔) | 의도=[스킬], 챔피언=[1:대상], 스킬=전체 |
| `이전: 없음 \| 질문: 탱커 챔피언중에 하나만 추천해줘` (역할군은 자리표시로 바꾸지 않음) | 의도=[추천], 역할군=탱커, 개수=하나 |
| `이전: 없음 \| 질문: [챔피언1] 궁극기 많이 바뀌었는지 최대한 과거 패치내역부터 지금까지 분석해줘` | 의도=[패치], 챔피언=[1:대상], 스킬=R, 시점=이력, 방향=변경, 개수=전체 |
| `이전: 의도=템트리 나=[챔피언1] \| 질문: 상대는 [챔피언2]야` | 의도=[템트리], 챔피언=[1:나, 2:상대], 이어받음=true |
| `이전: 의도=템트리 나=[챔피언1] 라인=원딜 \| 질문: 전체 템트리는?` | 의도=[템트리], 챔피언=[1:나], 라인=원딜, 개수=전체, 이어받음=true |
| `이전: 없음 \| 질문: 오늘 날씨 어때` | 범위=사이트밖 (나머지 null) |
| `이전: 없음 \| 질문: [챔피언1] E플 가능해?` (아리) | 범위=데이터밖, 챔피언=[1:대상], 스킬=E — 답: "스킬 상호작용은 아직 답할 수 없어요" + 아리 E 설명 |
| `이전: 없음 \| 질문: 이거 뭐하는 사이트임` | 범위=롤, 의도=[안내] |

## 5. 해석 틀 → 답 조립

- 의도마다 답 모듈 하나. 의도가 여러 개면 **중요한 순서대로 모듈을 이어 붙인다** (예: 상대법 → 템트리).
- 모듈은 해석 틀 조건으로 후보를 **넓게** 가져오고, 근거 판별 MiniGPT(실험 12에서 재학습 예정)가 점수를 매겨 **기준을 넘는 줄을 모두** 채택. 하나도 없으면 "찾지 못했어요".

| 의도 | `개수` 기본값 | 방향·시점 처리 |
|---|---|---|
| 개요 | 전체 (프로필·설명·스킬 5개·템트리) | — |
| 스킬 | `스킬` 있으면 하나, 없으면 전체 | — |
| 패치 | 최신 패치의 해당 줄 전체 | `방향`이 상향/하향이면 그 방향 줄만, 없으면 "이번엔 하향이었어요"처럼 사실대로. `이력`이면 패치별로 나열 |
| 성능 | 라인별 승률·경기 수 + 최근 패치 방향 요약 | "통계는 상관관계" 문구 |
| 추천 | 3~5명 (`개수=하나`면 1명) | 난이도 쉬움 → Data Dragon 난이도 낮은 순, 아니면 승률 순 |
| 범위=사이트밖 | — | "롤 질문만 답할 수 있어요" + 예시 질문 3개 |
| 범위=데이터밖 | — | 답할 수 없는 이유 + 가까운 정보(있으면) |

상향·하향 판단(패치 줄이 상향인지)은 답 모듈 쪽 일이다. 수치 비교 규칙(피해량↑ 상향, 재사용 대기시간↑ 하향)으로 먼저 하고, 근거 판별 재학습(실험 12) 때 방향 오답을 넣어 MiniGPT가 배우게 한다.

## 6. MiniGPT 학습 형식 (실험 11)

**생성 대신 '분류 머리'를 단다.** pretrain_v4 몸통은 그대로 쓰고, 출력층만 필드별로 붙인다.
- 문장 전체 머리 (마지막 토큰): 범위(3), 의도(11개 각각 예/아니오), 스킬(7), 라인(6), 역할군(7), 난이도(2), 시점(4), 방향(4), 개수(3), 이어받음(2)
- 자리표시 머리 (각 `[챔피언k]`의 `]` 토큰): 역할(나/상대/대상/맞대결/관계없음)
- 의도 순서: '첫 의도' 머리(의도 11개 중 하나)가 맨 앞, 나머지는 의도별 예/아니오 점수 높은 순
- 이유: 7.2M 모델이 JSON을 생성하면 형식이 깨질 수 있고, 필드별 정확도를 따로 재기 어렵다. 분류 머리는 형식 오류가 없고 빠르며 필드별로 평가된다. (`[챔피언1]`은 토큰 4개, 입력 길이는 192 토큰 안에 충분)

## 7. 선생님 LLM 데이터 생성 지시 (요약 — 상세 프롬프트는 생성 단계에서)

- 출력: JSON 한 줄 = `{"이전": …, "질문": "실제 이름이 들어간 질문", "틀": {…}}`. 서비스 코드의 사전으로 다시 자리표시로 바꾸고, 바꾼 결과가 틀의 자리와 안 맞으면 버린다(자동 검증).
- 예시: 실제 로그 질문을 말투 참고용으로 보여 준다. **실제 질문 63개는 평가용이라 그대로 생성 데이터에 넣지 않는다.**
- 구성 목표: 의도별 고르게 + 사이트밖 15% + 데이터밖 10% + 이어지는 질문 20% + 의도 2개 이상 20%. 오타·줄임말·반말·띄어쓰기 생략 포함.
- 챔피언은 학습용과 평가용으로 나눈다 (실험 10처럼 처음 보는 챔피언 이름에 대한 일반화 확인).

## 8. 평가

- **실제 질문 세트**: 11주차 로그 63개 (+ 이후 로그). 사용자 태그(`intent_gold`)를 이 틀로 옮겨 정답 작성.
- 지표: 범위 정확도(특히 사이트밖 거절), 의도 정확도(첫 의도 / 집합 일치), 나·상대 역할 정확도, 필드별 정확도, 틀 전체 일치율.
- 비교 기준: 지금 규칙(`search.parse`)을 이 틀로 옮긴 결과. 11주차 로그에서 규칙 의도 정확도 69%.
